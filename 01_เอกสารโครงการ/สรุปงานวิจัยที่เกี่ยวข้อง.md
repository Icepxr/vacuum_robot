# สรุปงานวิจัยที่เกี่ยวข้อง — หุ่นยนต์อเนกประสงค์เก็บขยะ + อ่านมิเตอร์

> เอกสารนี้สรุปงานวิจัยที่ค้นได้จากฐานข้อมูลวิชาการ (Consensus / Semantic Scholar, PubMed, Scopus, ArXiv) แบ่งเป็น 3 หมวดตามภารกิจของโครงการ พร้อมอธิบายว่าแต่ละงาน **เกี่ยวข้องกับโครงการเราอย่างไร** และ **ต่อยอดได้อย่างไร**
>
> โครงการอ้างอิง: หุ่นยนต์ Multi-task เก็บขยะ (30 ชิ้น ~5×5×5 มม.) + อ่านมิเตอร์น้ำ 3 จุด/ไฟฟ้า 1 จุด บนสนาม 100×250 ซม. ภายใน 3 นาที ควบคุมด้วย Joystick, ประมวลผลด้วย Raspberry Pi 5 + ESP32

---

## ภาพรวมและข้อสรุปสำคัญ (TL;DR)

- **การอ่านมิเตอร์**: แนวทางมาตรฐานคือ 2 ขั้นตอน — (1) ตรวจจับบริเวณตัวเลข/หน้าปัดด้วย YOLO หรือ Faster R-CNN แล้ว (2) อ่านตัวเลขด้วย OCR (CRNN, Tesseract, Transformer-OCR) ความแม่นยำระดับ 90–97% และทำได้เรียลไทม์ (~0.18 วินาที/เฟรม) — **นำมาใช้กับภารกิจอ่านมิเตอร์ของเราได้โดยตรง**
- **หุ่นยนต์เก็บขยะ**: ใช้ CNN/YOLO ตรวจจับขยะแล้วควบคุมมอเตอร์เข้าเก็บ ความแม่นยำ 80–95% หลายงานรันบน Raspberry Pi / Jetson — **สถาปัตยกรรมใกล้เคียงกับเรามาก**
- **Object detection บน Edge**: มีโมเดลขนาดเล็ก (Tinier-YOLO, MobileNet+YOLO, YOLO-tiny) และเทคนิคบีบอัด/quantization ที่ทำให้รันเรียลไทม์บนอุปกรณ์ทรัพยากรจำกัดได้ — **สำคัญมากเพราะเรารันหลายโมเดลพร้อมกันบน Pi 5**
- **ช่องว่างที่โครงการเราเติมเต็ม**: งานส่วนใหญ่ทำ *ภารกิจเดียว* โครงการเราบูรณาการ *เก็บขยะ + อ่านมิเตอร์* ในหุ่นยนต์ตัวเดียว ภายใต้ข้อจำกัดเวลาและทรัพยากร

## หมวดที่ 1: การอ่านค่ามิเตอร์อัตโนมัติ (Automatic Meter Reading — AMR)

ภารกิจอ่านมิเตอร์น้ำ/ไฟของเราตรงกับหมวดนี้ที่สุด งานเหล่านี้ให้ทั้ง pipeline, โมเดล, และชุดข้อมูลที่หยิบมาใช้ได้

### 1.1 Liang et al. (2022) — Research on water meter reading recognition based on deep learning
*Scientific Reports · 21 citations*

- **ทำอะไร**: เปรียบเทียบ Faster R-CNN, SSD, YOLOv3 สำหรับตรวจจับและอ่านมิเตอร์น้ำแบบเข็ม/ตัวเลข วิธีที่ดีที่สุด (YOLOv3 + crop bounding box) ได้ความแม่นยำ **90.61%**
- **เกี่ยวกับเรา**: เป็น baseline อ้างอิงว่าการอ่านมิเตอร์น้ำด้วย deep learning ทำได้จริงและแม่นระดับใช้งานได้ ชี้ว่าการ crop เฉพาะบริเวณตัวเลขก่อนอ่านช่วยเพิ่มความแม่นยำมาก
- **ต่อยอด**: ใช้แนวทาง "detect ROI → crop → recognize" กับมิเตอร์น้ำ 3 จุดของเรา และนำผลเปรียบเทียบโมเดลมาเลือกตัวที่เบาพอสำหรับ Pi 5

### 1.2 Salomon et al. (2020) — Deep Learning for Image-based Automatic Dial Meter Reading: Dataset and Baselines
*IJCNN · 54 citations*

- **ทำอะไร**: สร้างชุดข้อมูลมิเตอร์เข็มจริง (UFPR-ADMR) + baseline ตรวจจับหน้าปัดได้ **F1 100%** (Faster R-CNN/YOLO) อ่านค่าได้ 93.6% ต่อ dial แต่ 75.25% ต่อมิเตอร์ทั้งตัว พร้อมวิเคราะห์ error
- **เกี่ยวกับเรา**: มี **ชุดข้อมูลสาธารณะ** ให้ใช้ฝึก/ทดสอบ และชี้ปัญหาที่เจอจริง (อ่านทั้งมิเตอร์ยากกว่าทีละหลัก) ซึ่งเราต้องเจอเช่นกัน
- **ต่อยอด**: ขอชุดข้อมูล UFPR-ADMR มา pre-train แล้ว fine-tune กับมิเตอร์ในสนามจริงของเรา (ลดจำนวนภาพที่ต้องเก็บเอง)

### 1.3 Fan et al. (2022) — Real Time Power Equipment Meter Recognition Based on Deep Learning
*IEEE Transactions on Instrumentation and Measurement · 41 citations*

- **ทำอะไร**: โมเดล lightweight สำหรับอ่าน **มิเตอร์ไฟฟ้า** ในสถานีไฟฟ้า ใช้ adaptive anchor + Global Context + FPN/PANet ได้ **123 FPS**, 88.2% mAP และยังได้ 80.9% แม้ข้อมูลฝึกน้อย + เปิดชุดข้อมูล/โค้ด (GitHub)
- **เกี่ยวกับเรา**: ตรงกับ **ภารกิจมิเตอร์ไฟฟ้า** ของเราโดยตรง เน้น lightweight + เร็ว เหมาะกับข้อจำกัดเวลา 3 นาที
- **ต่อยอด**: นำสถาปัตยกรรม lightweight + โค้ดสาธารณะมาปรับใช้บน Pi 5; เทคนิค "ได้ผลดีแม้ข้อมูลน้อย" มีประโยชน์เพราะเราเก็บภาพมิเตอร์ได้จำกัด

### 1.4 Martinelli et al. (2022) — Water Meter Reading for Smart Grid Monitoring
*Sensors · 36 citations*

- **ทำอะไร**: ใช้ YOLOv5s ระบุตำแหน่งและอ่านตัวเลขจากมิเตอร์เข็ม พร้อม case study จริง วางบริบทว่า AMR สำคัญต่อ Smart Grid
- **เกี่ยวกับเรา**: ใช้เป็นเหตุผลเชิงบริบท (motivation) ในบทนำ และยืนยันว่า YOLOv5 เพียงตัวเดียวก็ทำ localize+recognize ได้
- **ต่อยอด**: ใช้ YOLOv5s/v8 เป็นตัวตั้งต้นเดียวสำหรับทั้ง detect + read เพื่อลดจำนวนโมเดลบน Pi 5

### 1.5 Yusva et al. (2025) — Vision-Based Smart Water Meter Reading Using YOLO Detection and OCR
*ICETISI · ใหม่ล่าสุด*

- **ทำอะไร**: Pipeline 3 ขั้น — YOLO หา ROI → preprocess (grayscale, ลด noise, ปรับ contrast, deskew) → **Tesseract OCR** อ่านค่า ได้ precision 0.97, mAP@50 96.4%, **0.18 วินาที/เฟรม**
- **เกี่ยวกับเรา**: เป็น pipeline ที่ **ทำตามได้ง่ายที่สุด** เพราะ Tesseract เป็น open-source ติดตั้งบน Pi ได้ และมีขั้น preprocess ที่ช่วยเรื่องแสง/มุมกล้อง (ปัญหาที่เราต้องเจอในสนาม)
- **ต่อยอด**: ใช้เป็น **สถาปัตยกรรมหลักของภารกิจอ่านมิเตอร์**: YOLOv8 (ROI) + OpenCV preprocess + Tesseract/PP-OCR บน Pi 5

### 1.6 Bay Nguyen van et al. (2025) — Water Meter Reading Based on Text Recognition Techniques and Deep Learning
*IEEE Access · 7 citations*

- **ทำอะไร**: ใช้ YOLOv8 หา counter region แล้วเปรียบเทียบ OCR 6 แบบ (PP-OCRv3, SPIN, Transformer-OCR, RobustScanner, SAR, CRNN) ในสภาพแวดล้อมหลากหลาย
- **เกี่ยวกับเรา**: เป็น **คู่มือเลือก OCR** ให้เรา — บอกว่าตัวไหนแม่น/เร็ว/ทนสภาพแวดล้อมต่างกัน
- **ต่อยอด**: ใช้ตารางเปรียบเทียบเลือก OCR ที่สมดุลระหว่างความแม่นและความเร็วบน edge

### 1.7 Shen et al. (2023) — Water Meter Reading Recognition Based on Deep Learning
*ICADMIT · 3 citations*

- **ทำอะไร**: DBNet (text detection) + CRNN (recognition) + เทคนิค "agent character" แก้ปัญหา **ครึ่งตัวอักษร** (half-digit ที่เข็มหมุนค้างระหว่างเลข) ทำงานได้ดีในแสงน้อย/สะท้อน/เอียง/บดบัง
- **เกี่ยวกับเรา**: ปัญหา half-digit เป็นปัญหาจริงของมิเตอร์แบบตัวเลขหมุน ซึ่งเรามีโอกาสเจอ
- **ต่อยอด**: นำเทคนิคจัดการ half-digit มาใช้ตอน label ข้อมูลและออกแบบ post-processing

### 1.8 Fan et al. (2024) — Image Recognition and Reading of Single Pointer Meter Based on Deep Learning
*IEEE Sensors Journal · 16 citations*

- **ทำอะไร**: อ่าน **มิเตอร์เข็มชี้** ด้วย YOLOv5 + perspective transform แก้หน้าปัดเอียง + U2NET (ปรับปรุงด้วย attention) หาเข็ม/ขีดสเกล + CRAFT/CRNN error เฉลี่ย < 5%
- **เกี่ยวกับเรา**: ถ้ามิเตอร์น้ำ/ไฟในสนามเป็นแบบเข็ม งานนี้ให้วิธีแก้มุมกล้องเอียง (perspective correction) ที่หุ่นยนต์เคลื่อนที่มักเจอ
- **ต่อยอด**: ใส่ขั้น perspective transform ก่อนอ่านค่า เพื่อชดเชยมุมที่หุ่นยนต์จอดไม่ตรง

### 1.9 Zhang et al. (2025) — Water meter reading recognition method based on character attention mechanism
*PLOS One · 2 citations*

- **ทำอะไร**: ResNet-FPN หา reading area + character attention + LeNet-5 ปรับปรุง เพิ่มความแม่นการอ่านทีละหลัก 8.8%/5.5% ทนมุมกล้องและแสง
- **เกี่ยวกับเรา**: เทคนิค attention ช่วยลด noise พื้นหลัง — มีประโยชน์เมื่อพื้นหลังสนามรก
- **ต่อยอด**: เป็นทางเลือกเพิ่มความแม่นถ้า OCR พื้นฐานยังพลาดในบางหลัก

### 1.10 Santiago et al. (2020) — Deployment framework for the Internet of water meters using computer vision on ARM platform
*J. Ambient Intelligence and Smart Environments · 6 citations*

- **ทำอะไร**: ระบบอ่านมิเตอร์ด้วย CV + SVM-OCR รันบน **แพลตฟอร์ม ARM (Linux)** เก็บข้อมูล (ID, เวลา UTC, ค่าที่อ่าน, ภาพ) และส่งขึ้น cloud
- **เกี่ยวกับเรา**: Pi 5 ก็เป็น ARM/Linux — งานนี้เป็น **ต้นแบบการ deploy บนฮาร์ดแวร์แบบเดียวกับเรา** รวมถึงการ log ข้อมูล
- **ต่อยอด**: ยืมโครงสร้างการบันทึกผล (timestamp + ค่าที่อ่าน + ภาพหลักฐาน) มาออกแบบระบบบันทึกของเรา

## หมวดที่ 2: หุ่นยนต์ทำความสะอาด/เก็บขยะด้วย Computer Vision

หมวดนี้ตรงกับภารกิจเก็บขยะ และหลายงานมี **สถาปัตยกรรมฮาร์ดแวร์คล้ายเรา** (Pi/Jetson + มอเตอร์ + กลไกเก็บ)

### 2.1 Bai et al. (2018) — Deep Learning Based Robot for Automatically Picking Up Garbage on the Grass
*IEEE Transactions on Consumer Electronics · 131 citations (อ้างอิงสูงสุดในหมวด)*

- **ทำอะไร**: หุ่นยนต์เก็บขยะบนสนามหญ้า ใช้ DNN ตรวจจับขยะ (**แม่น 95%**) + ground segmentation เพื่อ navigate โดยไม่ต้อง path planning ซับซ้อน
- **เกี่ยวกับเรา**: เป็น **งานอ้างอิงหลัก** ของภารกิจเก็บขยะ พิสูจน์ว่า detect + เคลื่อนเข้าเก็บอัตโนมัติทำได้จริง
- **ต่อยอด**: ยืมกลยุทธ์ navigation ที่ไม่ต้อง path planning เต็มรูปแบบ (เหมาะกับสนามเล็ก 100×250 ของเรา + ควบคุม Joystick)

### 2.2 Carcamo et al. (2024) — AI-Powered Cleaning Robot: A Sustainable Approach to Waste Management
*HSI · 4 citations*

- **ทำอะไร**: หุ่นยนต์เก็บขยะใช้ **Jetson Nano (แขนกล) + Raspberry Pi (การเคลื่อนที่)** + YOLO ตรวจจับ mAP >80% ให้ข้อมูลระยะ (83–95%) และทิศทาง (84–97%) เคลื่อนเข้าเก็บที่ระยะกำหนดแล้วทิ้งลงถัง
- **เกี่ยวกับเรา**: **สถาปัตยกรรมใกล้เรามาก** — แยกหน้าที่ระหว่างบอร์ดประมวลผล (Pi) กับตัวควบคุม เหมือน Pi 5 + ESP32 ของเรา และมีแนวคิด "เข้าเก็บที่ระยะที่กำหนด"
- **ต่อยอด**: ใช้แนวคิดประเมิน **ระยะ+ทิศทาง** จาก bounding box เพื่อสั่งกลไกเก็บขยะให้ทำงานเมื่อเข้าใกล้เป้า

### 2.3 An et al. (2024) — Research of Garbage Cleaning Robot Based on Deep Learning
*ICEMCE*

- **ทำอะไร**: หุ่นยนต์เก็บขยะโปรแกรมบน **Raspberry Pi** ใช้ image recognition หาชนิด/ตำแหน่งขยะ แล้วเคลื่อนไปเก็บ + จับด้วยกลไก
- **เกี่ยวกับเรา**: รันบน Pi เหมือนเรา เป็นตัวอย่างการทำ pipeline detect → move → grab บนฮาร์ดแวร์งบจำกัด
- **ต่อยอด**: เป็น reference implementation ของ flow การเก็บขยะบน Pi

### 2.4 Long et al. (2026) — Autonomous Garbage-Collecting Robot For Beaches
*Journal of Applied Technology and Innovation · 2 citations*

- **ทำอะไร**: ใช้ **Pi camera + CNN (TensorFlow)** แยกขยะ/ไม่ใช่ขยะ, ติดตามวัตถุจาก bounding box coordinates, ควบคุมมอเตอร์ปรับตำแหน่ง + กลไก **ใบมีดหมุนกวาด** ขยะเข้าตะแกรง มีประตูเทเมื่อเต็ม
- **เกี่ยวกับเรา**: ให้ไอเดีย **กลไกเก็บ (กวาด/ตะแกรง)** ที่เหมาะกับขยะชิ้นเล็ก และการติดตามด้วยพิกัด bbox → ควบคุมมอเตอร์ ตรงกับโหมด Joystick + ช่วยเล็งของเรา
- **ต่อยอด**: พิจารณากลไกกวาด/ดูดสำหรับขยะ 5 มม. และ logic แปลง bbox → คำสั่งมอเตอร์

### 2.5 Jin et al. (2023) — Garbage detection and classification using deep learning machine vision
*Waste Management · 121 citations*

- **ทำอะไร**: ปรับปรุง MobileNetV2 + attention + transfer learning + PCA ให้รัน **real-time บน Raspberry Pi 4B** (inference ~600 ms) แม่น 89–90% พร้อมต้นแบบคัดแยกขยะ
- **เกี่ยวกับเรา**: พิสูจน์ว่าโมเดลตรวจ/แยกขยะรันบน **Pi ได้จริง** พร้อมตัวเลข inference time ให้ประเมิน budget เวลา
- **ต่อยอด**: ถ้าต้องแยกประเภทขยะ ใช้ MobileNetV2 แบบบีบอัดนี้; ตัวเลข 600 ms/frame ช่วยวางแผนว่าใน 3 นาทีเก็บได้กี่ชิ้น

### 2.6 Haldorai et al. (2023) — Improved SSD for Smart Vision-Based Water Garbage Cleaning Robot
*Cognitive Robotics · 32 citations*

- **ทำอะไร**: ปรับปรุง SSD ตรวจจับขยะ **mAP 94.099%, 64.67 FPS** สำหรับหุ่นยนต์เก็บขยะผิวน้ำอัตโนมัติ
- **เกี่ยวกับเรา**: แม้เป็นขยะผิวน้ำ แต่เทคนิค detector ที่เร็ว+แม่นใช้อ้างอิงการเลือกโมเดลได้
- **ต่อยอด**: เป็นตัวเปรียบเทียบ SSD กับ YOLO เมื่อเลือก detector

### 2.7 Tian et al. (2022) — Modified YOLOv4 for vision-based underwater garbage cleaning robot
*Frontiers of IT & Electronic Engineering · 37 citations*

- **ทำอะไร**: YOLOv4 ดัดแปลง 4-scale + model pruning **66.67 FPS, mAP 95.099%**
- **เกี่ยวกับเรา**: เทคนิค **pruning เพื่อเพิ่มความเร็ว** ตรงกับความต้องการรันเร็วบน edge ของเรา
- **ต่อยอด**: ใช้ pruning ลดขนาดโมเดลตรวจจับขยะให้รันไหวพร้อมโมเดลอ่านมิเตอร์บน Pi 5

### 2.8 Kong et al. (2021) — IWSCR: Intelligent Water Surface Cleaner Robot
*IEEE Transactions on Systems, Man, and Cybernetics · 79 citations*

- **ทำอะไร**: หุ่นยนต์ทำ **3 ภารกิจอัตโนมัติ** — cruise+detect, track+steer, grasp+collect ใช้ YOLOv3 + sliding-mode controller
- **เกี่ยวกับเรา**: เป็นตัวอย่าง **ระบบหลายภารกิจในหุ่นยนต์ตัวเดียว** (ใกล้แนวคิด multi-task ของเรา) และแยก pipeline detect/track/grasp ชัดเจน
- **ต่อยอด**: ยืมโครงสร้างแบ่งสถานะการทำงาน (state machine: cruise → track → grasp) มาออกแบบ flow ของเรา

### 2.9 Tamgadge et al. (2024) — Autonomous Floating Garbage Collection Device
*ICACS*

- **ทำอะไร**: ใช้ **ESP32-CAM + Arduino UNO** สตรีมภาพไปประมวลผลด้วย Python บน server, YOLOv3 ตรวจขยะ + ultrasonic กันชน
- **เกี่ยวกับเรา**: ใช้ **ESP32** ในระบบเหมือนเรา และมีรูปแบบ "สตรีมภาพไปประมวลผลที่หน่วยแรงกว่า" (คล้าย ESP32 ↔ Pi 5) + ใช้ ultrasonic กันชน
- **ต่อยอด**: พิจารณา ESP32-CAM เป็นกล้องเสริม และเพิ่ม ultrasonic กันชนในหุ่นยนต์เรา

### 2.10 Hasany et al. (2021) — Autonomous robotic system for collecting garbage over small water bodies
*CACRE · 18 citations*

- **ทำอะไร**: navigate + CV ตรวจขยะ + โฟกัส area of interest เช็คว่าขยะอยู่ในระยะเก็บไหม + กลไกกันขยะหลุด + retrain detector ได้
- **เกี่ยวกับเรา**: แนวคิด "**เช็คว่าเป้าอยู่ในระยะเก็บก่อนสั่งกลไก**" ตรงกับ workflow เก็บขยะของเรา
- **ต่อยอด**: ออกแบบ logic ตรวจระยะก่อน trigger กลไก และออกแบบภาชนะกันขยะหลุด

## หมวดที่ 3: Object Detection บน Edge / Embedded Device

หมวดนี้สำคัญเชิงวิศวกรรม เพราะเราต้องรัน **หลายโมเดลพร้อมกัน** (ตรวจขยะ + อ่านมิเตอร์) บน Raspberry Pi 5 ภายใต้เวลา 3 นาที

### 3.1 Fang et al. (2019) — Tinier-YOLO: A Real-Time Object Detection Method for Constrained Environments
*IEEE Access · 309 citations (อ้างอิงสูงสุดในหมวด)*

- **ทำอะไร**: ย่อ Tiny-YOLOv3 ด้วย fire module (SqueezeNet) + dense connection ได้โมเดล **8.9 MB (เล็กกว่า 4 เท่า)**, 25 FPS บน Jetson TX1, mAP ดีขึ้น
- **เกี่ยวกับเรา**: เป็น **ตัวเลือกโมเดลตรวจจับที่เบามาก** เหมาะกับ Pi 5 ที่ต้องแบ่งทรัพยากร
- **ต่อยอด**: ใช้ Tinier-YOLO (หรือแนวคิดย่อโมเดล) เป็น detector หลักของขยะ

### 3.2 Ravi et al. (2022) — Real-Time Embedded Implementation of Improved Object Detector for Resource-Constrained Devices
*J. Low Power Electronics and Applications · 24 citations*

- **ทำอะไร**: ปรับ loss (bounding box regression) ใน YOLOv5 แล้ว deploy ด้วย **ROS 2 บน NVIDIA Jetson Xavier NX** ทดสอบเรียลไทม์
- **เกี่ยวกับเรา**: ให้แนวทาง deploy บน embedded + ใช้ **ROS 2** เป็น framework เชื่อมส่วนต่างๆ (มีประโยชน์ถ้าเราจะจัดระเบียบการสื่อสาร Pi 5 ↔ ESP32)
- **ต่อยอด**: พิจารณาใช้ ROS 2 จัด node ตรวจขยะ/อ่านมิเตอร์/ควบคุมมอเตอร์

### 3.3 Kim et al. (2025) — Concurrent Multi-Frame Processing for Real-Time Object Detection on Edge
*IEEE Access · 11 citations*

- **ทำอะไร**: แบ่งเฟรมประมวลผล **ขนานตามจำนวน core** บน Jetson Orin Nano ลด runtime/หน่วยความจำ/พลังงานได้มาก (สูงสุด 445%/69%/73%)
- **เกี่ยวกับเรา**: Pi 5 มี 4 core — เทคนิคนี้ช่วย **รันหลายงานขนานกัน** (ตรวจขยะ + อ่านมิเตอร์) ให้ทันเวลา
- **ต่อยอด**: ออกแบบ multi-threading/multi-process บน Pi 5 เพื่อใช้ทุก core เต็มที่

### 3.4 Lee et al. (2021) — YOLO with Adaptive Frame Control for Real-Time Object Detection
*Multimedia Tools and Applications · 151 citations*

- **ทำอะไร**: เพิ่ม Adaptive Frame Control (AFC) ให้ YOLO ลด service delay บน embedded ที่ทรัพยากรจำกัด โดยคงความแม่น
- **เกี่ยวกับเรา**: ช่วยจัดการ **latency** เมื่อกล้องส่งเฟรมเร็วกว่าที่ Pi ประมวลผลไหว
- **ต่อยอด**: ใส่ frame skipping/AFC เพื่อไม่ให้คิวภาพล้นตอนหุ่นเคลื่อนที่

### 3.5 Kim et al. (2023) — Real-time object detection using domain-based transfer learning for edge devices
*ICAIIC · 5 citations*

- **ทำอะไร**: transfer learning เฉพาะ domain (เลือกเฉพาะวัตถุที่สนใจ) ทำให้ YOLOv7-tiny แม่นใกล้ YOLOv7 แต่ **เร็วขึ้น 389%** บน Jetson
- **เกี่ยวกับเรา**: สนามเรามีวัตถุจำกัด (ขยะ, มิเตอร์) — การ **จำกัด domain** ช่วยให้โมเดลเล็กแต่แม่น
- **ต่อยอด**: ฝึกเฉพาะคลาสที่เจอในสนาม (ขยะ/มิเตอร์น้ำ/มิเตอร์ไฟ) เพื่อเพิ่มความเร็ว

### 3.6 Khurana et al. (2025) — MOLO: Hybrid MobileNet + YOLO for Object Detection on Resource Constrained Devices
*Discover Artificial Intelligence · 4 citations*

- **ทำอะไร**: ผสาน MobileNetV2 (เบา) + YOLOv8-s (แม่น) เพื่อสมดุลความเร็ว/ความแม่นบนอุปกรณ์จำกัด
- **เกี่ยวกับเรา**: แนวคิด hybrid — ใช้โมเดลเบาสำหรับงานที่ต้องเร็ว (ตรวจขยะระหว่างเคลื่อนที่) และตัวแม่นสำหรับงานที่ต้องนิ่ง (อ่านมิเตอร์)
- **ต่อยอด**: จัดสรรโมเดลตามภารกิจ — เบาสำหรับ real-time detect, แม่นสำหรับ OCR ตอนจอดนิ่ง

### 3.7 Al Amin et al. (2024) — FPGA-Based Real-Time Object Detection Using YOLO for Edge Computing
*IEEE Access · 82 citations*

- **ทำอะไร**: YOLOv3-tiny บน FPGA (Kria KV260) **15 FPS, 99% accuracy, ใช้ไฟเพียง 3.5W**
- **เกี่ยวกับเรา**: แสดงทางเลือกฮาร์ดแวร์ประหยัดพลังงานสุดขั้ว (FPGA) — เป็นข้อมูลเปรียบเทียบ ถ้าอนาคตต้องการประหยัดแบตมากๆ
- **ต่อยอด**: ทางเลือกระยะยาว หากต้องการ inference เฉพาะทางที่กินไฟต่ำกว่า Pi

### 3.8 Kim et al. (2026) — AHCO-YOLO: Algorithm–Hardware Co-Optimization for Energy-Efficient Detection on Edge
*IEEE Transactions on VLSI Systems · 1 citation*

- **ทำอะไร**: co-optimize โมเดล+ฮาร์ดแวร์ (quantization + dataflow) บน FPGA ได้ 79.8 FPS ที่ประสิทธิภาพพลังงานสูง
- **เกี่ยวกับเรา**: หลักการ **quantization** นำมาใช้บน Pi 5 ได้ (เช่น INT8) เพื่อเร่งความเร็ว
- **ต่อยอด**: quantize โมเดลเป็น INT8 (TFLite/ONNX Runtime) เพื่อรันเร็วขึ้นบน Pi

### 3.9 Zhang et al. (2025) — Edge-Optimized Lightweight YOLO for Real-Time SAR Object Detection
*Remote Sensing · 9 citations*

- **ทำอะไร**: backbone แบบ inverted residual + FastFPN ลดเหลือ **1.9M params, 4.4 GFLOP** รัน 30–34 FPS บน Jetson TX2
- **เกี่ยวกับเรา**: เทคนิคลด params/FLOP ใช้เป็นแนวทางออกแบบโมเดลเบาสำหรับ Pi
- **ต่อยอด**: อ้างอิงเทคนิคออกแบบ backbone เบาถ้าจะ custom โมเดลเอง

### 3.10 Liu et al. (2026) — FEGW-YOLO: Lightweight Framework for Real-Time Multi-Crop Detection on Edge
*Sensors*

- **ทำอะไร**: กรอบบีบอัดตาม "Compress, Compensate, Refine" (Ghost Conv + attention) ได้ 95.1% mAP ลด params 54.7% รัน 38 FPS/12.3W บน Jetson Xavier + รองรับ multi-modal sensor
- **เกี่ยวกับเรา**: ปรัชญาบีบอัดแล้วชดเชยความแม่น + แนวคิด **เหลือ headroom ให้ประมวลผลงานอื่นขนาน** ตรงกับที่เราต้องรันหลายงาน
- **ต่อยอด**: ใช้แนวคิดบีบอัดโมเดลให้เหลือทรัพยากรพอสำหรับทั้งตรวจขยะและอ่านมิเตอร์พร้อมกัน

## สรุปแนวทางต่อยอดสำหรับโครงการ (Recommendations)

**สถาปัตยกรรมที่แนะนำจากงานวิจัย:**

1. **ภารกิจอ่านมิเตอร์** → ทำตาม pipeline ของ Yusva (1.5) และ Bay Nguyen (1.6): `YOLOv8 หา ROI → OpenCV preprocess (deskew/contrast) → OCR (Tesseract/PP-OCR/CRNN)` เสริม perspective transform (1.8) และการจัดการ half-digit (1.7)
2. **ภารกิจเก็บขยะ** → ทำตาม Carcamo (2.2) และ Bai (2.1): `YOLO ตรวจขยะ → ประเมินระยะ/ทิศจาก bbox → เข้าใกล้ → trigger กลไกเมื่ออยู่ในระยะ (2.10)` กลไกกวาด/ตะแกรงตาม Long (2.4)
3. **การจัดการทรัพยากรบน Pi 5** → quantize INT8 (3.8), ใช้โมเดลเบา Tinier-YOLO/YOLO-tiny (3.1, 3.5), ประมวลผลขนานหลาย core (3.3), จำกัด domain เฉพาะคลาสในสนาม (3.5), และ frame control กัน latency (3.4)
4. **การจัดระบบซอฟต์แวร์** → พิจารณา ROS 2 (3.2) จัด node และ state machine แบบ IWSCR (2.8): `cruise → detect → (เก็บขยะ | อ่านมิเตอร์) → next`
5. **การบันทึกผล** → ยืมโครงสร้าง log ของ Santiago (1.10): timestamp + ค่าที่อ่าน + ภาพหลักฐาน

**ชุดข้อมูลที่ใช้ได้ทันที:** UFPR-ADMR (1.2, มิเตอร์เข็ม), PMIs dataset + โค้ด GitHub (1.3, มิเตอร์ไฟฟ้า)

**จุดขายเชิงวิชาการของโครงการ (novelty):** งานวิจัยเกือบทั้งหมดทำ *ภารกิจเดียว* — โครงการเราบูรณาการ **เก็บขยะ + อ่านมิเตอร์น้ำ + อ่านมิเตอร์ไฟฟ้า** ในหุ่นยนต์ตัวเดียว บนสถาปัตยกรรม Pi 5 + ESP32 ภายใต้ข้อจำกัดเวลา ซึ่งเป็นช่องว่างที่ยังมีงานน้อย

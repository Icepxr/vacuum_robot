# ระบบกล้อง — สถาปัตยกรรมที่ล็อกแล้ว

**หน้าที่:** กล้องถ่ายรูปมิเตอร์เฉยๆ · Pi 5 จัดการทั้งหมด · OCR ดึงตัวเลขออกมา · เก็บเข้าฐานข้อมูล

```
กล้อง → Pi 5 ─┬─ ถ่ายภาพ (เสาต้องนิ่งแล้ว)
              ├─ preprocess ด้วย OpenCV
              ├─ OCR ดึงตัวเลข
              ├─ เขียนลงไฟล์ในเครื่องทันที   ← ห้ามข้าม
              └─ sync ขึ้น cloud เมื่อเน็ตพร้อม
```

## 🔴 กติกาข้อเดียวที่ห้ามละเมิด: เขียนลงเครื่องก่อนเสมอ

**เน็ตต้องไม่ใช่จุดตายของภารกิจ** ถ้าสนามแข่งไม่มี WiFi หรือหลุดกลางคัน หุ่นต้องทำงานต่อได้และข้อมูลต้องไม่หาย

| ทำแบบนี้ | ห้ามทำแบบนี้ |
|---|---|
| ถ่ายเสร็จ → เขียน `.jsonl` + เซฟไฟล์ภาพลง SD ทันที | ยิงขึ้น cloud ตรงๆ แล้วถือว่าเสร็จ |
| upload เป็นงานเบื้องหลัง ล้มเหลวก็ลองใหม่ทีหลังได้ | ให้ภารกิจรอผลการ upload |
| ถ้า sync ไม่ได้เลย ก็ยังมีข้อมูลครบใน SD | ข้อมูลอยู่แค่ใน RAM รอส่ง |

| | **Supabase** | Google Sheet |
|---|---|---|
| การยืนยันตัวตนบน Pi | URL + API key ใส่ใน header ครั้งเดียว | ต้องมี service account JSON + จัดการ token refresh |
| จำนวนชิ้นส่วนที่ต้องติดตั้ง | `requests` อย่างเดียวก็พอ | `gspread` + `google-auth` |
| ตำแหน่งเซิร์ฟเวอร์ | มีโปรเจกต์อยู่แล้วที่ **ap-southeast-1 (สิงคโปร์)** | สหรัฐฯ/ทั่วโลก |
| ดูข้อมูลด้วยตา | ต้องเปิด dashboard | เปิดชีตดูได้ทันที ครูตรวจง่าย |
| เก็บไฟล์ภาพด้วย | ได้ (Storage) | ไม่ได้ ต้องใช้ Drive แยก |

**แนะนำ Supabase** เพราะบน Pi ใช้แค่ `requests.post()` ครั้งเดียว ไม่มี OAuth ให้พัง และเก็บภาพต้นฉบับไว้ตรวจย้อนหลังได้ในที่เดียวกัน

> ⚠️ **ต้องเปิดโปรเจกต์ Supabase ใหม่** — โปรเจกต์ที่มีอยู่ (`MCCMU's Project`) เป็นของงานอื่น
> มีตาราง `members` · `albums` · `places` · `docs` · `audit_log` 101 แถว ชัดว่าเป็นเว็บชมรม **ห้ามเอาข้อมูลหุ่นไปปนที่นั่น**

## โครงตารางที่เสนอ

```sql
create table meter_readings (
  id            bigserial primary key,
  captured_at   timestamptz not null default now(),
  run_id        text,              -- แยกว่าเป็นการวิ่งรอบไหน
  meter_type    text,              -- 'water' | 'electric'
  raw_text      text,              -- ตัวอักษรดิบที่ OCR อ่านได้
  value         numeric,           -- ค่าที่ parse แล้ว (null ถ้าอ่านไม่ออก)
  confidence    real,              -- ความมั่นใจจาก OCR
  image_path    text,              -- ไฟล์ภาพต้นฉบับใน SD / Storage
  synced_at     timestamptz        -- null = ยังไม่ได้ sync
);
```

**`raw_text` กับ `image_path` สำคัญพอๆ กับ `value`** — เก็บไว้เพื่อให้ตรวจย้อนหลังได้ว่า OCR อ่านผิดตรงไหน และถ้า OCR พลาด ยังมีภาพให้คนอ่านเองได้

## เรื่องที่ยังตัดสินไม่ได้ จนกว่าจะเห็นรูปมิเตอร์

**มิเตอร์เป็นแบบไหนเปลี่ยนวิธีทำทั้งหมด:**

| ชนิดมิเตอร์ | วิธีที่ใช้ได้ |
|---|---|
| ตัวเลขกลไกหมุน (แบบมิเตอร์น้ำทั่วไป) | Tesseract + preprocess ธรรมดา ใช้ได้ดี |
| จอ **7-segment** | **Tesseract อ่านไม่ค่อยได้** ต้องใช้วิธีเฉพาะ เช่น `ssocr` หรือแบ่งส่วนแล้วดูว่าขีดไหนติด |
| เข็มชี้ | OCR ใช้ไม่ได้เลย ต้องหามุมเข็มด้วย Hough transform |

**สิ่งที่ต้องการจากคุณ: ถ่ายรูปมิเตอร์ที่จะใช้แข่งมา 1 รูป** แล้วจะบอกได้ทันทีว่าใช้ทางไหน

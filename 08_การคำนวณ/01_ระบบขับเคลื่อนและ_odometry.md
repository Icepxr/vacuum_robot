## 1.1 อัตราทดเกียร์ 56:1 — มาจากการอนุมาน ไม่ใช่จาก datasheet

**สมมติฐาน:** มอเตอร์ 520 (แกนเปล่า) ที่ 12 V หมุนราว 9,000–10,500 rpm ซึ่งเป็นย่านปกติของมอเตอร์ตระกูลนี้

```
rpm_มอเตอร์เปล่า = rpm_เพลาออก × อัตราทด
178 × 56 = 9,968 rpm      ← อยู่ในย่านปกติ ✓
178 × 30 = 5,340 rpm      ← ต่ำผิดปกติสำหรับ 12 V ✗
178 × 70 = 12,460 rpm     ← สูงเกินจริง ✗
```

**ผล:** อัตราทด = **56:1** — **[คำนวณ/อนุมาน]** ไม่ใช่ [สเปก]

> ### ✅ ยืนยันด้วยการวัดจริงแล้ว — 5 ก.ย. 2026 (M1/T1)
> หมุนเพลาออกด้วยมือ **5 รอบ** นับได้ **12,460 counts** = **2,492 counts/รอบ**
> เทียบค่าที่คาดของ 56:1 (2,464) → **+1.14 %** อยู่ในเกณฑ์ ±1.4 % ของไฟล์ 15 §15.6.1
>
> **อัตราทด 56:1 และ COUNTS_PER_REV = 2,464 จึงเป็น [วัดจริง] แล้ว — ไม่ต้องแก้ `config.h`
> และไม่ต้องคำนวณไฟล์นี้ใหม่**
>
> ตัวเลือกอื่นถูกตัดทิ้งหมด: 60:1 ต้องได้ 13,200 (ห่าง −5.6 %) · 19/30:1 ต้องได้ 6,600 · 131:1 ต้องได้ 28,820
> **วัดครบสองข้างแล้ว:** ซ้าย 2,492 /รอบ (+1.14 %) · ขวา 2,456.8 /รอบ (−0.29 %) · เฉลี่ย 2,474 (+0.42 %)
> ต่างกันเอง 1.43 % = อยู่ในความคลาดเคลื่อนการหมุนมือ → **เกียร์บ็อกซ์สองตัวอัตราทดเดียวกัน**
> ยังไม่ได้ทำวิธียืนยันที่ 2 (วัดความยาวเกียร์บ็อกซ์ด้วยเวอร์เนีย) เพราะไม่มีเวอร์เนีย — แต่วิธีนับ pulse ให้ผลชัดเจนพอแล้ว
> ⚠ **เครื่องหมายฝั่งขวาเป็นลบ ยังไม่สรุปว่าต้องตั้ง `invert` หรือไม่** — รอ T2 ตัดสิน

> ⚠ ตัวเลขนี้เป็น **ฐานของ odometry ทั้งระบบ** ถ้าผิด ทุกอย่างในไฟล์นี้ผิดตาม
> **วิธียืนยัน 2 ทาง (ต้องทำทั้งคู่ที่ M1):**
> 1. วัดความยาวเกียร์บ็อกซ์ด้วยเวอร์เนีย — 56:1 ต้องได้ L ≈ 24 mm (22 mm = 19/30:1 · 26.5 mm = ≥131:1)
> 2. หมุนเพลาออกด้วยมือครบ 1 รอบ แล้วนับ count ต้องได้ 2,464

## 1.2 ความเร็วสูงสุด

**สมมติฐาน:** ล้อ Ø90 mm ไม่ลื่นไถล · 178 rpm คือค่าที่เพลาออกตอน**ไม่มีโหลด**

```
v_max = (rpm / 60) × π × D
      = (178 / 60) × π × 0.090 m
      = 2.9667 rev/s × 0.28274 m/rev
      = 0.8388 m/s
```

**ผล: v_max ≈ 0.839 m/s (เปล่า) = 3.02 km/h** — **[คำนวณ]**
มีโหลดจริงอาจเหลือ ~0.671 m/s ถ้าใช้สมมติฐานเดิม 80% ของค่าเปล่า — **[ประมาณการ]** ตัวเลข 80% นี้ไม่มีที่มาในเอกสาร ต้องวัดที่ M2

> ค่าเดิมบนล้อ Ø65 mm คือ **0.606 m/s** และค่ามีโหลดประมาณ **0.48 m/s** — **SUPERSEDED 13 ก.ย. 2026**

### duty ที่ต้องใช้ (สมมติความเร็ว ∝ duty แบบเชิงเส้น — จริงเฉพาะเมื่อโหลดคงที่)

```
duty(0.15 m/s) = 0.15 / 0.8388 = 17.9%  ≈ 18%
duty(0.30 m/s) = 0.30 / 0.8388 = 35.8%  ≈ 36%
```

## 1.3 ความเร็วหมุนตัว (differential drive)

```
ω_max = v_max / (track/2) = 0.8388 / 0.090 = 9.32 rad/s = 534 °/s
```

ข้อจำกัดที่ตั้งไว้ในซอฟต์แวร์คือ ω ≤ 1.5 rad/s → ใช้แค่ **16%** ของค่าทางทฤษฎี

## 1.4 ความละเอียด Encoder / Odometry

**สมมติฐาน:** encoder 11 PPR ต่อรอบมอเตอร์ · อ่านแบบ quadrature ×4 · อัตราทด 56

```
counts ต่อรอบล้อ = 11 PPR × 4 × 56 = 2,464 counts/rev
```

```
ความละเอียดระยะทาง = π × D / counts_ต่อรอบ
                    = π × 90 mm / 2,464
                    = 282.74 / 2,464 = 0.11475 mm/count
```

```
ความละเอียดการหมุนตัว:
หมุนหุ่น 1° → ล้อแต่ละข้างเดินทาง = (track/2) × θ = 90 mm × 0.017453 rad = 1.5708 mm
                                   = 1.5708 / 0.11475 = 13.69 ≈ 13.7 counts ต่อ 1°
```

```
อัตรา count ที่ความเร็วเต็ม = 2.9667 rev/s × 2,464 = 7,310 counts/s ต่อล้อ
```

| รายการ | ค่า | ป้าย |
|---|---|---|
| counts/รอบล้อ | **2,464** | [คำนวณ] ต้องยืนยันที่ M1 |
| ความละเอียด odometry | **0.1147 mm/count** | [คำนวณ] |
| counts ต่อ 1° ของการหมุนตัว | 13.7 | [คำนวณ] |
| counts/s ที่เต็มสปีด | 7,310 ต่อล้อ | [คำนวณ] |

> ความละเอียดเดิมบนล้อ Ø65 mm คือ **0.0829 mm/count** และ **19.0 counts/°** — **SUPERSEDED 13 ก.ย. 2026**

## 1.5 PCNT ล้นใน 4.5 วินาที

ESP32 PCNT เป็นตัวนับ **16 บิตมีเครื่องหมาย** → ชนเพดานที่ 32,767

```
t_overflow = 32,767 counts / 7,310 counts/s = 4.48 s
```

**ผล: ตัวนับล้นภายใน 4.5 วินาทีที่ความเร็วเต็ม** — **[คำนวณ]**
**ทางแก้ที่ล็อกไว้แล้ว:** ตั้ง `pcnt_unit_add_watch_point()` ที่ ±30,000 แล้วสะสมเข้าตัวแปร `int64_t` ฝั่งซอฟต์แวร์

> เหตุผลที่ต้องใช้ PCNT ไม่ใช่ ISR: 7,310 interrupt/s/ล้อ × 2 ล้อ = 14,620 interrupt/s — ISR จะกิน CPU และนับพลาดเมื่อ CPU ยุ่ง

## 1.6 แรงบิดที่ล้อต้องการ — ฐานออกแบบปัจจุบัน

**สมมติฐาน (สำคัญ — ตัวเลขนี้ไวต่อค่า Crr มาก):**
- น้ำหนักออกแบบรวมที่ล้อรองรับ W = **30 N** → มวลสมมูล M = 30/9.81 = **3.06 kg**
- รัศมีล้อ r = **45 mm = 0.045 m**
- แบ่งโหลดเท่ากัน 2 ล้อขับ
- สัมประสิทธิ์ความต้านทานการกลิ้ง Crr: กระเบื้อง **0.05** · พรม **0.20** — **[ประมาณการ]** ไม่มีแหล่งอ้างอิงในเอกสาร
- กรณีทางลาด 20° คิดบนพรม (Crr = 0.20) ด้วย

```
สูตร:  T_ต่อล้อ = F_รวม × r / 2
       F_รวม (ทางราบ)  = Crr · W
       F_รวม (ทางลาด α) = W·(sin α + Crr·cos α)
```

| สถานการณ์ | แทนค่า | F_รวม | T ต่อล้อ |
|---|---|---|---|
| กระเบื้อง (Crr 0.05) | 0.05 × 30 | 1.500 N | 0.0338 N·m = **0.34 kgf·cm** |
| พรม (Crr 0.20) | 0.20 × 30 | 6.000 N | 0.1350 N·m = **1.38 kgf·cm** |
| ไต่ลาด 20° บนพรม | 30 × (0.34202 + 0.20×0.93969) | 15.899 N | 0.3577 N·m = **3.65 kgf·cm** |

*(แปลงหน่วย: 1 kgf·cm = 0.0980665 N·m)*

**เทียบพิกัดมอเตอร์:** JGB37-520 ที่ 178 rpm มีแรงบิดปกติราว **2.5–3.5 kgf·cm** (stall 8–10) — **[ประมาณการ ยังไม่มี datasheet ยืนยัน]**

| กรณี | Safety margin |
|---|---|
| กระเบื้อง | 2.5 / 0.34 = **SF 7.3** |
| พรม | 2.5 / 1.38 = **SF 1.82** |
| ลาด 20° บนพรม | 2.5 / 3.65 = **SF 0.69** 🔴 ไม่ผ่านถ้าพิกัดจริงอยู่ที่ 2.5 kgf·cm |
| ลาด 20° บนพรม (ขอบบนประมาณการมอเตอร์) | 3.5 / 3.65 = **SF 0.96** 🔴 ยังต่ำกว่า 1 |

> **ข้อสรุปปัจจุบัน:** มีแนวโน้มเพียงพอสำหรับพื้นราบ แต่ยังไม่สามารถยืนยันการไต่ทางลาด 20° บนพรมได้ จากพิกัดมอเตอร์ 2.5–3.5 kgf·cm ที่เคยประมาณไว้ ค่า SF อยู่เพียง 0.69–0.96 จึงต้องวัดแรงบิดจริง ลดข้อกำหนดความชัน หรือตัดสินใจเปลี่ยนอัตราทด/มอเตอร์

## 1.7 stall-as-bumper (G5) — ระยะที่หุ่นดันวัตถุต่อไปหลังชน

**สมมติฐาน:** เวลาตรวจจับ 300 ms และหุ่นยังเดินหน้าด้วยความเร็วเดิมตลอดช่วงนั้น (เป็นค่า worst case)

```
ระยะดัน = v × t_detect
0.30 m/s × 0.300 s = 90 mm
0.15 m/s × 0.300 s = 45 mm   ← เลือกจำกัด 0.15 m/s (G14) เพราะเหตุนี้
```

**เกณฑ์ตัดสิน stall:** |Δencoder| < 20 counts ต่อเนื่อง 300 ms ขณะ |PWM| > 30%

```
counts ปกติที่ 0.15 m/s ใน 300 ms = 45 mm / 0.11475 mm/count = 392 counts
เกณฑ์ 20 counts = 5.1% ของค่าปกติ → ยังห่างมาก ไม่หลอนง่าย ✓
```

## 1.8 ทำไม DRV8871 ไม่ใช่ TB6612FNG (ตัวเลขเปรียบเทียบ)

| | TB6612FNG | DRV8871 ×2 |
|---|---|---|

**เหตุผลเชิงตัวเลข:** JGB37-520 กิน 0.65 A ตอนวิ่งปกติ **[สเปก]** แต่ stall คาดว่า ~2–3 A **[ประมาณการ — 3–5 เท่าของค่าปกติ ตามพฤติกรรมทั่วไปของมอเตอร์เกียร์ตระกูลนี้ ยังไม่วัด]**
→ 2–3 A เกินพิกัดต่อเนื่อง 1.2 A ของ TB6612FNG และเฉียดพีค 3.2 A
→ ตั้งจำกัดกระแส DRV8871 ไว้ที่ **~2.5 A ต่อมอเตอร์**

> ⚠ **ต้องวัดกระแส stall จริงที่ M1/ทดสอบ 1.2 ตารางที่ 3** ก่อนสรุปว่า 2.5 A เป็นค่าที่ถูก — ตอนนี้ไม่มี INA226 แล้ว วงจรจำกัดกระแสของ DRV8871 คือชั้นป้องกันฮาร์ดแวร์ชั้นเดียวที่เหลือ

### 1.16.1 เปลี่ยน RPM_FULL_DUTY 152 → 178 rpm (4 ต.ค. 2026 · ผู้ใช้: "มอเตอร์ 12 V 178 rpm")

**SUPERSEDES ตารางสูตรใน §1.16** (V_hw 692 / W_hw 5324 / K 1446) — สูตรเดิม เปลี่ยนแค่ n

**เหตุผลว่าทำไม 178 มีหลักฐานดีกว่า 152 สำหรับ DRV8871:** 152 rpm วัดตอนมอเตอร์ได้แค่ 10.29 V เพราะ L298N ตกคร่อม 1.71 V [วัดจริง ไฟล์ 15 §15.2.5 · แหล่งจ่าย 12.00 V · 0.259 A ไร้โหลด]
- ปรับเป็น 12 V (rpm ไร้โหลด ∝ แรงดันโดยประมาณ ไม่คิด I·R ขดลวด): 152 × 12.00/10.29 = **177.3 rpm** → ตรงสเปก 178 ต่างกัน 0.4 % [คำนวณ]
- DRV8871: R_DS(on) HS+LS 565 mΩ typ [สเปก ไฟล์ 15] → ตก 0.259 × 0.565 = 0.146 V → 152 × (12.00 − 0.146)/10.29 = **175.1 rpm** [ประมาณการ]
- เลือก 178 [สเปก] ตามผู้ใช้ — ต่างจาก 175.1 แค่ 1.7 % ถ้าของจริงเป็น 175 หุ่นจะวิ่งช้ากว่าตัวเลขที่สั่ง 1.6 %

| ค่า | สูตร | แทนค่า | ผล | ป้าย |
|---|---|---|---|---|
| V_hw | n·πD/60 | 178 × π × 87 / 60 = 810.84 mm/s | **810 mm/s** | [คำนวณจากสเปก] |
| W_hw | V_hw/(B/2) ปัดขึ้น | 810 / 130 = 6.2308 rad/s | **6231 mrad/s** (≈357 °/s) | [คำนวณ] |
| K | 10⁶/V_hw ปัดขึ้น | 10⁶ / 810 = 1234.57 | **1235 ‰/(m/s)** | [คำนวณ] |

ตรวจ: trunc(810 × 1235/1000) = 1000 ‰ · h = trunc(6231 × 260/2000) = 810 → 1000 ‰

**duty ที่ล้อได้ (host audit · core จริง + สูตร drive.js):** ตรง 50/75/100 % = 500/750/1000 ‰ · หมุน 700/749/1000 ‰ · โค้ง 0/1000 · 199/1000 · 333/1000 ‰ → **เท่า §1.16 และเท่าก่อน C61 (±2 ‰)** — ค่า n ไม่เปลี่ยนความรู้สึกตอนขับ เพราะปุ่มเป็น % ของเพดานซึ่งคิดจาก n ตัวเดียวกัน เปลี่ยนแค่ความหมายของตัวเลข mm/s, rad/s

**ข้อจำกัด:** 178 คือ**ไร้โหลด**ที่ 12 V พอดี — บนพื้นมีน้ำหนัก ~3 kg [ผู้ใช้ประมาณ] rpm ต่ำกว่านี้ (ยังไม่วัด) และราง 12 V มาจาก buck ถ้าแรงดันจริงต่ำกว่า 12 V rpm ลดตาม · open-loop จึงวิ่งช้ากว่าคำสั่งเสมอจนกว่าจะมี PID จาก encoder · ยืนยันด้วย `m t3` (ยกล้อ) ได้ค่า [วัดจริง] บน DRV8871

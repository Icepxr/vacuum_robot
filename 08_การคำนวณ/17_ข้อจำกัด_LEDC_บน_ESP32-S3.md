# 17 — ข้อจำกัดของ LEDC บน ESP32-S3: ความถี่คู่กับความละเอียดที่ตั้งได้จริง

**สร้าง 6 ก.ย. 2026** · พบตอนตรวจเฟิร์มแวร์ M3 ก่อนนำไปใช้จริง
**ผลที่ตามมา:** ตาราง LEDC ใน `system_architecture.md` §3.5 **มี 2 แถวจาก 4 แถวที่ตั้งค่าตามนั้นไม่ได้** → บันทึกเป็น **C15** ในไฟล์ 10

---

## 17.1 สูตรและขอบเขต

LEDC ตั้งความถี่ด้วยตัวหารเลขทศนิยมคงที่ ค่าที่คำนวณได้ต้องอยู่ในช่วงที่ฮาร์ดแวร์รับได้

```
สูตร:  div_param = (f_clk × 256) / (freq × 2^res)

เงื่อนไขที่ต้องผ่านพร้อมกันทั้งสองข้อ:
  256 ≤ div_param ≤ 262,143        (262,143 = 0x3FFFF)
  res ≤ 14                         (เพดานความละเอียดของ ESP32-S3)
```

| ที่มา | ค่า | ป้าย |
|---|---|---|
| ขอบล่าง 256 · ขอบบน 262,143 (0x3FFFF) | จากซอร์ส `esp_driver_ledc/src/ledc.c` ของ ESP-IDF v5.5 | **[สเปก — ยืนยันทางอ้อม]** ⚠ |
| เพดานความละเอียด 14 บิต ของ ESP32-S3 | จาก `soc_caps.h` (`SOC_LEDC_TIMER_BIT_WIDTH`) | **[สเปก — ยืนยันทางอ้อม]** ⚠ |
| ESP32-S3 ไม่มี clock mux แยกต่อ timer | ไม่มี `SOC_LEDC_HAS_TIMER_SPECIFIC_MUX` ใน `soc_caps.h` | **[สเปก — ยืนยันทางอ้อม]** ⚠ |
| แหล่งนาฬิกาที่ S3 มี | APB 80 MHz และ XTAL 40 MHz เท่านั้น (ไม่มี RC_FAST) | **[สเปก — ยืนยันทางอ้อม]** ⚠ |

> **บอกตรงๆ เรื่องแหล่ง:** ค่าเหล่านี้มาจากการที่ agent ตรวจซอร์สของ ESP-IDF v5.5 มา **ผมตรวจเลขคำนวณซ้ำเองแล้วทุกบรรทัด แต่ยังไม่ได้เปิดไฟล์ซอร์สเอง**
> **วิธียืนยันขั้นเด็ดขาดที่ทำได้เลย:** ตั้ง `PWM_RES_BITS = 10` แล้วสั่ง `pwm on` — ถ้าทฤษฎีนี้ถูก `ledcAttach()` จะคืน false และเฟิร์มแวร์จะพิมพ์ `[ERR] ผูก LEDC กับขาไม่สำเร็จ`

**ตรวจความสมเหตุสมผลกับของที่ใช้งานได้จริงแล้ว:** เฟิร์มแวร์ M1 ใช้ 1 kHz ที่ 11 บิต และบิลด์+รันผ่านจริงเมื่อ 5 ก.ย. 2026
```
div = (80e6 × 256) / (1,000 × 2,048) = 20.48e9 / 2,048,000 = 10,000   ✓ อยู่ในช่วง
```
สูตรทำนายว่าใช้ได้ และของจริงก็ใช้ได้ → **สูตรสอดคล้องกับผลการทดลองที่มีอยู่** — **[คำนวณตรวจทาน]**

## 17.2 ช่วงความถี่ที่ตั้งได้จริงในแต่ละความละเอียด (แหล่งนาฬิกา APB 80 MHz)

```
f_ต่ำสุด = (80e6 × 256) / (262,143 × 2^res)
f_สูงสุด = (80e6 × 256) / (256 × 2^res) = 80e6 / 2^res
```

| ความละเอียด (บิต) | duty สูงสุด | ความถี่ต่ำสุด | ความถี่สูงสุด |
|---:|---:|---:|---:|
| 8 | 255 | 305.18 Hz | 312,500 Hz |
| 9 | 511 | 152.59 Hz | 156,250 Hz |
| 10 | 1,023 | **76.29 Hz** | 78,125 Hz |
| 11 | 2,047 | 38.15 Hz | 39,062 Hz |
| 12 | 4,095 | 19.07 Hz | 19,531 Hz |
| **13** | **8,191** | **9.54 Hz** | **9,766 Hz** |
| 14 | 16,383 | 4.77 Hz | 4,883 Hz |

**[คำนวณ]** · ถ้าใช้ XTAL 40 MHz ให้หารช่วงทั้งสองด้วย 2

> **อ่านตารางนี้ยังไง:** ยิ่งต้องการความละเอียด duty สูง ยิ่งลงความถี่ต่ำได้ แต่ขึ้นความถี่สูงไม่ได้
> **ที่ 10 บิต ลงต่ำสุดได้แค่ 76.29 Hz** → ทุกความถี่ที่ต่ำกว่านั้นตั้งไม่ได้

## 17.3 ผลต่อตาราง LEDC ใน §3.5 — ตรวจทีละแถว

| Timer ใน §3.5 | ความถี่ | ความละเอียดที่ §3.5 เขียน | div_param บน APB | ผล |
|---|---:|---:|---:|---|
| T0 มอเตอร์ล้อ | 20 kHz | 11 บิต | 500 | ✅ **ใช้ได้** (แต่บน XTAL ได้ 250 < 256 → **บังคับใช้ APB**) |
| T1 แปรง | 20 kHz | 10 บิต | 1,000 | ✅ ใช้ได้ |
| **T2 เซอร์โว** | **50 Hz** | **16 บิต** | — | 🔴 **ตั้งไม่ได้ — เกินเพดาน 14 บิตของ S3** |
| **T3 blower** | **25 Hz** | **10 บิต** | **800,000** | 🔴 **ตั้งไม่ได้ — เกินเพดาน 262,143** |

**ค่าที่ใช้แทนได้ พร้อมการตรวจสอบ:**

**T2 เซอร์โว 50 Hz → ใช้ 14 บิต**
```
div = 20.48e9 / (50 × 16,384) = 25,000                    ✓ อยู่ในช่วง
ความละเอียดพัลส์ = 20 ms / 16,384 = 1.2207 µs
```
MG996R ใช้พัลส์ช่วง 1,000–2,000 µs → **ละเอียดกว่าที่ต้องการ 800 เท่า เหลือเฟือมาก** — **[คำนวณ]**

**T3 blower 25 Hz → ต้องใช้อย่างน้อย 12 บิต**
```
12 บิต: div = 20.48e9 / (25 ×  4,096) = 200,000           ✓
13 บิต: div = 20.48e9 / (25 ×  8,192) = 100,000           ✓
14 บิต: div = 20.48e9 / (25 × 16,384) =  50,000           ✓
```

**T0 บังคับให้ทั้งบอร์ดล็อกที่ APB**
S3 ไม่มี clock mux แยกต่อ timer → timer ทั้ง 4 ตัวใช้แหล่งนาฬิกาเดียวกันหมด
T0 ที่ 20 kHz/11 บิต ใช้ XTAL ไม่ได้ (div = 250 < 256) → **ทั้งบอร์ดต้องอยู่บน APB 80 MHz**
→ ตัวเลขในตาราง 17.2 (ที่คิดบน APB) จึงเป็นตัวเลขที่ใช้จริง ไม่มีทางเลือกอื่น — **[คำนวณ]**

## 17.4 ค่าที่เลือกใช้ในเฟิร์มแวร์ M3 และเหตุผล

เฟิร์มแวร์ `src/blower_test/` อนุญาตช่วงความถี่ **10–50 Hz** (เพดาน 50 Hz เป็นการบังคับตาม §3.5 ที่ห้าม PWM ความถี่สูงกับ blower)

หาความละเอียดที่ครอบทั้งช่วงนี้ได้ด้วยค่าเดียว:
```
เงื่อนไขที่ผูกมัดคือขอบล่าง 10 Hz:
  2^res ≥ (80e6 × 256) / (10 × 262,143) = 20.48e9 / 2,621,430 = 7,812.5
  → 2^res ≥ 7,813  →  res ≥ 13
ตรวจขอบบน 50 Hz ที่ 13 บิต: div = 20.48e9 / (50 × 8,192) = 50,000   ✓
```

**ผลลัพธ์: เลือก `PWM_RES_BITS = 13` (duty สูงสุด 8,191)** — ครอบ 10–50 Hz ได้ทั้งช่วงด้วยค่าเดียว — **[คำนวณ]**

ตรวจว่าเลขไม่ล้นในโค้ด: `(dutyPercent × PWM_MAX) / 100` ค่าสูงสุด = 100 × 8,191 = **819,100** ยังอยู่ในช่วงของ `int` 32 บิตสบายๆ ✓

> ค่าเดิมที่เขียนไว้ 10 บิตตาม §3.5 ทำให้ `ledcAttach()` คืน false และ **ขั้นทดสอบ S5 ทั้งขั้นรันไม่ได้เลย**
> ล้มแบบปลอดภัย (ไม่มีอันตรายทางฮาร์ดแวร์) แต่ทดสอบไม่ได้

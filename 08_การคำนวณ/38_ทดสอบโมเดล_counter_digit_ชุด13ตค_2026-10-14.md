- conf ของ PyTorch กับ NCNN ต่างกันมาก (0.35 vs 0.79 บนรูปเดียวกัน) ทั้งที่กรอบตรงกัน — น่าจะเพราะ letterbox ไม่เหมือนกัน (ultralytics ใช้ rect 1280×736 · สคริปต์ NCNN ใช้จัตุรัส 1280×1280) [ประมาณการ]

## 38.5 เวลา [วัดจริง]

| เครื่อง | counter @1280 | digit @640 | รวม | หมายเหตุ |
|---|---|---|---|---|
| Pi 5 NCNN 4 threads | 1669 ms | 400 ms | **2069 ms** | 58 °C |
| Pi 5 NCNN 2 threads | 1405 ms | 254 ms | **1659 ms** | |
| Mac M2 PyTorch | ~130 ms | ~15 ms | ~145 ms | |
| `cells` บน Pi (ไฟล์ 26 §26.9) | — | — | 82 ms (REAI) / 336 ms (ทางสำรอง) | |

สูตรเทียบ: counter 1280² มีพิกเซล (1280/640)² = **4 เท่า** ของ 640² → เดิม counter 640 บน Pi ~380 ms (ไฟล์ 26) × 4 ≈ 1520 ms [คำนวณ] ใกล้ค่าวัด 1405–1669 ms ✓
→ ถ้าใช้จริงต้องรันแบบ async หลังถ่าย (คนขับรอ ~2 s) · ลด imgsz เป็น 640 แล้ว counter หาไม่เจอเลยในชุดนี้ (PyTorch 0/9 ที่ conf 0.01 ยกเว้นจุดขอบภาพ)

## 38.6 สรุป [ยังไม่ตัดสินใจ — ผู้ใช้ตัดสิน]

- **ยังไม่ควรสลับเป็น YOLO แทน `cells`:** อ่านถูกเท่ากัน (3/8) แต่ช้ากว่า ~20 เท่าบน Pi และชนิดน้ำ/ไฟกลับด้านทุกครั้ง
- จุดแข็งของ YOLO ที่ `cells` ไม่มี: บอกชนิดมิเตอร์ (ถ้าแก้ label แล้วถูก) · digit อ่านตัวเลขทั่วไปได้ดีเมื่อได้กรอบ (5/8 แม้แถบเอียง)
- **ถ้าจะเทรนรอบต่อ** (ข้อเสนอ เรียงตามผลที่คาด): (1) ตรวจ `data.yaml` names ↔ label (ชนิดกลับ 4/4) · (2) เพิ่มรูปจาก BRIO บนหุ่นจริง ทั้งกล่องกลมและเหลี่ยม หลายระยะ/มุม (รูปใน `~/mrc/data/images` ใช้ได้เลย) · (3) เพิ่มตัวอย่าง "7" ฟอนต์การ์ด REAI + เส้นแบ่งช่องเอียงเป็น background · (4) ใส่รูปไม่มีมิเตอร์เป็น negative
- **`cells` เองก็พลาดกล่องทรงกลมทั้ง 3 รูป และอ่านกล่องว่างเป็น `29`** — ข้อนี้ต้องแก้ในโค้ดหลักไม่ว่าจะเลือกทางไหน (แยกเป็นงานถัดไป)

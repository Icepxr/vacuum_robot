### env `robot` — เฟิร์มแวร์รวม (7 ก.ย. 2026)

สั่งงานด้วย **prefix นำหน้าคำสั่งเดิมของแต่ละชุด** เพราะชุดคำสั่งเดิมชนกันหลายตัว (`?`, `s`, `d`, `f`, `st`, `c`)

| พิมพ์ | ไปที่ |
|---|---|
| `m <คำสั่ง>` | M1 ล้อ + เอ็นโคดเดอร์ |
| `sv <คำสั่ง>` | M2 เซอร์โว |
| `bl <คำสั่ง>` | M3 blower + แปรง |
| `stop` หรือ `!` | หยุดทุกระบบทันที |
| `st` · `il` | สถานะรวม · ตาราง interlock ที่บังคับอยู่ |
| `? m` · `? sv` · `? bl` | คำสั่งของชุดนั้น |

> **🔴 มี interlock บังคับอยู่ ไม่ใช่แค่รวมไฟล์เฉยๆ** — ตอนแยก env `build_src_filter`
> กันไม่ให้เปิดสองระบบพร้อมกันได้ทางกายภาพ พอรวมแล้วเกราะนั้นหายไป จึงย้ายมาไว้ในโค้ด
> ที่มาของกติกาและตัวเลขทุกตัว: [`08_การคำนวณ/18_interlock_เฟิร์มแวร์รวม.md`](../08_การคำนวณ/18_interlock_เฟิร์มแวร์รวม.md)
>
> | กติกา | ห้ามอะไร | เพราะ |
> |---|---|---|
> | **R1** | แปรง ↔ เซอร์โว ซ้อนกัน (เว้น 300 ms) | ราง 5 V/6 A — ถ้าเซอร์โว 2 ตัวจะเกินพิกัด 33 % (C12) |
> | **R2** | blower ↔ ล้อ ออกตัวซ้อนกัน (เว้น 1000 ms) | ราง 12 V/8 A เหลือ margin 7.5 % + inrush blower ยังไม่วัด |
> | **R4** | เปิด blower/แปรงระหว่างวัด rpm ของ M1 | รางตกแล้วผลวัดเพี้ยน — **ข้ามได้ด้วย `force <คำสั่ง>`** |
>
> R1 กับ R2 เป็นข้อจำกัดทางไฟฟ้า **ข้ามไม่ได้ทุกกรณี** · R4 เป็นเรื่องความถูกต้องของผลวัด จึงข้ามได้เมื่อจงใจ

**สามชุดเดิมยังแฟลชแยกได้เหมือนเดิมทุกอย่าง** — โค้ดทดสอบไม่ถูกแก้ตรรกะเลย ใช้ตอนต้องการผลวัดที่เทียบกับของเก่าได้

### ตรวจแล้ว: `platformio.ini` ปัจจุบันสอดคล้องกับข้อกำหนดข้างบน
`-D ARDUINO_USB_CDC_ON_BOOT=1` + `-D ARDUINO_USB_MODE=1` ทำให้ `Serial` ไปออกช่อง USB native
จึง**ไม่แย่งขา 43/44** ที่จองไว้ให้ Pi 5 — ตรงกับ §3.7 · `board = esp32-s3-devkitc-1`
(หมายเหตุ: บอร์ดในเอกสารระบุ **N16R8** = flash 16 MB + PSRAM 8 MB · ค่า default ของ
`esp32-s3-devkitc-1` ใน PlatformIO **ยังไม่ได้ตรวจว่าเปิด PSRAM/ตั้ง flash 16 MB ให้หรือไม่** —
ต้องยืนยันก่อนใช้ PSRAM จริง ยังไม่กระทบโค้ด Wi-Fi test ปัจจุบัน)

## ขั้น C — ลิงก์ Pi 5 ขั้นต่ำ (12 ก.ย. 2026 · C18 ปิดแล้ว)

`src/robot/comm.{h,cpp}` + `comm_codec.h` เปิด **`Serial0` = UART0 บน GPIO 44 (RX) / 43 (TX)** ที่ 115200 แยกจากคอนโซล USB · มีแค่ 2 ข้อความ

| พิมพ์ในคอนโซล USB | ทำอะไร | เห็นอะไรถ้าทำงาน |
|---|---|---|
| `cap` | ส่ง `#E,<ms>,CAPTURE_REQ,<n>*CC` ไป Pi แล้วรอ `$K` ไม่เกิน 5 s | `[comm] got $K,<n>,1 ใน ~140 ms` (ไฟล์ 19 §19.4.1) · ถ้าไม่มี Pi → `timeout` หลัง 5 s |
| `cs` | สถานะลิงก์: state · seq · roundtrip · นับ req/ok/fail/timeout/bad lines | |

**ก่อนต่อสาย Pi — ยืนยัน 2 อย่างบนบอร์ด (ยังไม่ได้ทำ):**
1. `Serial0` ออกขา 43/44 จริง: ต่อ USB-TTL (3.3 V) ที่ GPIO43 → RX ของ TTL, GND ร่วม · เปิด monitor 115200 · พิมพ์ `cap` → ต้องเห็น `#E,…,CAPTURE_REQ,1*XX` โผล่ฝั่ง TTL · ถ้าไม่โผล่ = core map `Serial0` ไปคนละขา (โค้ดระบุ 44/43 ใน `begin()` ตรงๆ แล้ว แต่ต้องเห็นของจริง)
2. ทางกลับ: พิมพ์ `$K,1,1*1E` จากฝั่ง TTL (ต่อ TX ของ TTL → GPIO44) → ESP32 ต้องพิมพ์ `got $K,1,1` · CRC `1E` มาจาก `crc8("K,1,1")` (เทสต์ `test/host_comm_codec.cpp`)

**ทดสอบ codec บน host โดยไม่ต้องมี PlatformIO** (ผ่านแล้ว 12 ก.ย. บน Mac):
```bash
clang++ -std=c++17 -I src/robot test/host_comm_codec.cpp -o /tmp/codec && /tmp/codec
```
vector เดียวกับ `11_pi5_vision/tests/test_protocol.py` — ถ้าสองฝั่งได้ CRC ต่างกัน ลิงก์จะเงียบสนิทโดยไม่มี error ใดๆ

⚠ **env `robot` ยังไม่เคยบิลด์จริง** (Mac ไม่มี PlatformIO) — บิลด์ครั้งแรกบน Windows · ถ้า `Serial0` ไม่มีในสโคป แปลว่า core/flag ไม่ตรงกับที่คาด (`ARDUINO_USB_CDC_ON_BOOT=1` ต้องเปิดอยู่ใน `[env]`)
